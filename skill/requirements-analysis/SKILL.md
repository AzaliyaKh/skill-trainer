# Requirements analysis

Trace findings to the supplied requirements. Separate confirmed contradictions from
missing information and assumptions. Do not silently invent business rules or
resolve conflicting requirements on the user's behalf.

For each material issue explain its consequence and propose a clarification or a
verifiable acceptance criterion. Preserve requirement identifiers so an expert can
trace conclusions back to the source.

Use the output format and paths requested by the task. For a table, keep one issue
or requirement per row. For a diagram, represent only supported entities and
relationships; distinguish unresolved decisions in labels. Check that the produced
artifact opens in its intended format and contains the required elements.

Use the requested output language for prose, table cells, and diagram labels.
Preserve machine-readable keys and source identifiers when a schema requires them.
