# Требования к генерации ТЗ: сервис управления задачами

## Цель

Подготовить краткое техническое задание на REST API: сервис управления задачами. Результат — один файл `answer.md` в Markdown на русском языке; реализация сервиса не требуется.

## Структура и стиль документа

Обязательные разделы: «Назначение», «API», «Хранение», «Допущения и открытые вопросы», «Критерии приёмки». В разделе API описать входы, успешный результат и ошибки каждой операции. Использовать нейтральные технические формулировки, точные имена маршрутов, полей и значения статусов. Сохранить идентификаторы API на языке интерфейса.

## Функциональные требования и ограничения

- `POST /tasks`: принять JSON с обязательным непустым `title`, создать задачу со статусом `todo`, вернуть созданную задачу в JSON.
- `GET /tasks`: вернуть JSON-массив всех задач; при отсутствии задач — пустой массив.
- `PATCH /tasks/{id}`: изменить название и/или статус существующей задачи и вернуть результат в JSON. Статусы только `todo`, `in_progress`, `done`; пустой `title` и недопустимый статус запрещены.
- `DELETE /tasks/{id}`: удалить задачу, вернуть JSON; после удаления обращения к этому id дают HTTP 404.
- Некорректный JSON и другие некорректные данные — HTTP 400; неизвестный id — HTTP 404. Все ответы — JSON.
- Допускается хранение в памяти процесса; сохранение после перезапуска не требуется.

## Неопределённые сведения

Не заданы: формат/генерация id, точные схемы ответов, успешные HTTP-статусы, порядок списка и допустимость пустого тела PATCH. Обозначить их как `[уточнить]` или открытые вопросы; возможные решения допускаются только с явной пометкой «допущение». Не добавлять обязательные авторизацию, внешнюю БД, нагрузочные показатели или иные неуказанные функции. Конкретные нормативные документы не заданы.

## Требования к итоговому результату

ТЗ должно покрывать все перечисленные операции, валидацию, форматы и хранение. Сформулировать проверяемые критерии приёмки для успешных операций, ошибок HTTP 400/404 и ограничений данных; не копировать готовую реализацию и не скрывать неизвестные значения.
