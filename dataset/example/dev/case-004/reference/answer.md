# Техническое задание: Task Management REST API

## 1. Назначение

Сервис создаёт, просматривает, изменяет и удаляет задачи.

## 2. API

### `POST /tasks`

Принимает JSON с непустым `title`, создаёт задачу со статусом `todo` и возвращает созданную задачу в JSON. Отсутствующий или пустой `title`, некорректный JSON и недопустимый статус дают HTTP 400.

### `GET /tasks`

Возвращает JSON-массив всех задач; при отсутствии задач — пустой массив.

### `PATCH /tasks/{id}`

Изменяет `title` и/или статус существующей задачи. Пустой `title`, неизвестный статус или некорректный запрос дают HTTP 400; неизвестный `id` — HTTP 404. Результат возвращается в JSON.

### `DELETE /tasks/{id}`

Удаляет существующую задачу и возвращает JSON. Неизвестный `id` даёт HTTP 404.

## 3. Хранение

Задачи хранятся в памяти процесса; сохранение после перезапуска не требуется.

## 4. Допущения и открытые вопросы

- Формат и способ генерации `id`, успешные HTTP-статусы и точные схемы ответов не заданы.
- Порядок задач в списке и допустимость пустого тела `PATCH` требуют согласования.

## 5. Критерии приёмки

1. Созданная с валидным `title` задача имеет статус `todo` и появляется в списке.
2. `PATCH` принимает только заявленные статусы и сохраняет разрешённые изменения.
3. После `DELETE` операции с тем же `id` возвращают HTTP 404.
4. Некорректные данные возвращают HTTP 400, неизвестные `id` — HTTP 404.
5. Все ответы представлены в JSON.
