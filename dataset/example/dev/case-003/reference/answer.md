# Техническое задание: URL Shortener REST API

## 1. Назначение

Сервис создаёт короткие коды для HTTP(S)-адресов, перенаправляет по ним и удаляет их.

## 2. API

### `POST /shorten`

Принимает JSON с исходным URL. Если URL имеет схему `http` или `https`, сервис создаёт уникальный код длиной 8 символов и возвращает его в JSON. Некорректный JSON, отсутствие URL и запрещённая схема дают HTTP 400 с JSON-описанием ошибки.

### `GET /{code}`

Для существующего восьмисимвольного кода возвращает перенаправление на сохранённый URL. Для отсутствующего или неизвестного кода возвращает HTTP 404 с JSON-описанием ошибки. Код неверной длины считается некорректным входом и даёт HTTP 400.

### `DELETE /{code}`

Удаляет существующую запись. Неизвестный код даёт HTTP 404; код неверной длины — HTTP 400. Ответ не является перенаправлением и возвращается в JSON.

## 3. Хранение

Соответствия «код → исходный URL» хранятся в памяти процесса. Сохранение после перезапуска не требуется.

## 4. Допущения и открытые вопросы

- Имена полей запросов и ответов, успешные HTTP-статусы и статус перенаправления не заданы; их нужно согласовать до реализации.
- Алфавит кода, способ генерации и обработка коллизий не заданы. Реализация должна гарантировать уникальность активных кодов.
- Поведение при повторном сокращении одного URL не определено.

## 5. Критерии приёмки

1. Валидный HTTP(S)-URL создаёт уникальный код ровно из 8 символов, доступный через `GET`.
2. `GET` существующего кода перенаправляет на сохранённый URL.
3. После успешного `DELETE` тот же код возвращает HTTP 404.
4. URL с иной схемой, отсутствующий URL и код неверной длины возвращают HTTP 400.
5. Неизвестный восьмисимвольный код возвращает HTTP 404.
6. Все ответы, кроме перенаправления, имеют JSON-представление.
