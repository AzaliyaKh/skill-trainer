# Техническое задание: Notification REST API

## 1. Назначение

Сервис создаёт уведомления, выдаёт их список и отмечает уведомления прочитанными.

## 2. API

### `POST /notifications`

Принимает JSON с непустым `message` длиной не более 500 символов. Создаёт уведомление с `read: false` и возвращает его в JSON. Отсутствующее, пустое или слишком длинное сообщение и некорректный JSON дают HTTP 400.

### `GET /notifications`

Возвращает JSON-массив всех уведомлений; при отсутствии данных — пустой массив.

### `PATCH /notifications/{id}/read`

Устанавливает существующему уведомлению `read: true` и возвращает результат в JSON. Неизвестный `id` даёт HTTP 404.

## 3. Хранение

Уведомления хранятся в памяти процесса; сохранение после перезапуска не требуется.

## 4. Допущения и открытые вопросы

- Формат и генерация `id`, успешные HTTP-статусы и точные схемы ответов не заданы.
- Порядок списка, повторная отметка прочитанного уведомления и измерение длины сообщения требуют согласования.

## 5. Критерии приёмки

1. Валидное сообщение до 500 символов создаёт уведомление с `read: false`.
2. Созданное уведомление появляется в JSON-списке.
3. `PATCH` существующего `id` устанавливает `read: true`.
4. Пустое, отсутствующее или слишком длинное сообщение возвращает HTTP 400.
5. Неизвестный `id` возвращает HTTP 404; все ответы представлены в JSON.
